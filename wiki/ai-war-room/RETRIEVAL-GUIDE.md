## 🔍 1. กฎการสืบค้นและเข้าถึงเอกสาร (Document Retrieval Rules)

เพื่อประหยัดโควตาและลดความแออัดของ Context (Token) ให้ AI ทุกตัวใช้หลักการ **"สืบค้นแบบเจาะจง ห้ามดึงไฟล์ทั้งก้อนหากไม่จำเป็น"**:

1. **ค้นหาก่อนเริ่มงาน:** 
   * ให้ใช้คำสั่ง `Grep` หรือ `glob` ค้นหาคีย์เวิร์ดใน `wiki/` ก่อน เพื่อดูว่าเคยมีไฟล์ความรู้นั้นอยู่แล้วหรือไม่
   * ห้ามสร้างไฟล์ความรู้ขึ้นใหม่ซ้ำซ้อน หากพบบันทึกเรื่องเดิมใน `wiki/` ให้ใช้การต่อท้าย (Append) หรือปรับปรุงเนื้อหาในไฟล์เดิม
2. **อ้างอิงตำแหน่งไฟล์แบบเจาะจง (Cross-Referencing):**
   * ห้ามคัดลอก (Paste) โค้ดหรือข้อความยาว ๆ ข้ามไฟล์ ให้ใช้รูปแบบการลิงก์อ้างอิง: `[REF: path/to/file.ext#Lstart-Lend]`
   * ในการคุยกันข้าม AI ให้ระบุเฉพาะจุดที่ต้องแก้ไขและบริบทสั้น ๆ (Zero-Context Handoff) เท่านั้น
3. **การเข้าถึงโฟลเดอร์สำหรับ B3 Second Brain:**
   * **ข้อมูลดิบ/บันทึกการประชุม:** อ่านจาก `raw/` เท่านั้น (ห้ามเขียนแก้ไขในโฟลเดอร์นี้)
   * **ความรู้ที่ผ่านการสังเคราะห์แล้ว:** อ่านและบันทึกที่ `wiki/` แยกตามโฟลเดอร์ของโปรเจกต์ เช่น `wiki/cit/`, `wiki/jong-jaroen/`, `wiki/b3-avenger/`
   * **ความรู้ด้านการทหาร/การแชร์ระบบทีม:** ให้อ่านจาก `wiki/ai-war-room/`

## 🔄 2. โปรโตคอลประสานงานข้ามโมเดล (Cross-Agent Synchronization Protocol)

เพื่อแก้ปัญหา "การกักขังข้อมูลเฉพาะตัว (Agent Silos)" และลดภาระคุณ B3 ในการพิมพ์สั่งงานวนลูป ให้บังคับใช้กติกาดังนี้:

1. **การอัปเดตกฎเกณฑ์ส่วนกลาง:**
   * หากคุณ B3 สั่งให้สร้างกฎใหม่, เพิ่มการเตือนความจำ (Reminders), หรือเปลี่ยนข้อตกลงระบบงานร่วมกัน -> AI ที่รับคำสั่ง **ต้องทำการบันทึกข้อมูลนั้นลงไฟล์ `กฏ.md` (Master Rules Gateway) บรรทัดแรก ๆ ทันที**
2. **การกระจายกฎเกณฑ์ไปยังเพื่อนร่วมทีม (Auto-Propagation):**
   * **กรณีเป็น Claude หรือ Codex (ผู้แก้ไขไฟล์ได้โดยตรง):** ให้ทำการอัปเดตข้อตกลงใหม่ลงใน `CLAUDE.md`, `GEMINI.md`, และ `CODEX.md` ของเพื่อน ๆ ในโปรเจกต์ทันทีใน Session เดียวกัน
   * **กรณีเป็น Gemini (มีข้อจำกัดด้านการเขียนไฟล์บางสภาวะ):** ให้เขียนรายละเอียดลงในไฟล์ `wiki/to-b3/GEMINI-RETURN-[task].md` และส่งคำสั่ง Trigger แจ้ง Claude/Codex ให้นำข้อตกลงใหม่ไปอัปเดตลงในไฟล์กติกาของตนเอง
3. **การรายงานอัปเดตระบบ:**
   * อัปเดตเสร็จแล้ว ให้รันคำสั่งแจ้งเปลี่ยนระบบกลางของทีม:
     ```bash
     node scripts/board-post.js --type changelog --agent [ชื่อ AI] --message "อัปเดตกฎการทำงานร่วมข้ามโมเดลเรื่อง [ระบุหัวข้อ]"
     ```

## ⚡ 3. ระบบติดตาม Token และโอนงานอัตโนมัติ (Token Limit Tracking & Auto-Handoff)

AI ทุกตัวมีหน้าที่สอดส่องและป้องกันปัญหา "หมดพลังงานกลางคัน (Token Exhaustion)":

1. **มอนิเตอร์โควตาของตนเอง:**
   * ทุกครั้งที่จบ Step การทำงาน ให้ประเมินจำนวน Token ที่เหลืออยู่
   * หาก Token ของโมเดลตัวเองใช้งานไปแล้ว **เกิน 80%** ของลิมิต หรือใกล้ครบโควตาจำกัดของวัน ให้ทำตามขั้นตอนต่อไปนี้ทันที
2. **การส่งสัญญาณแจ้งเตือน:**
   * ให้พิมพ์บันทึกสถานะเตือน `[ALERT] Token Quota Limit Approaching` ไว้ที่หัวข้อแจ้งเตือนใน `STATUS.md` เพื่อส่งสัญญาณให้ AI ตัวถัดไปที่เข้ามาทำงานทราบสถานะ
3. **การส่งมอบงานอัตโนมัติ (Auto-Handoff):**
   * หากประเมินว่างานมีโอกาสหลุดหรือค้าง ให้รันคำสั่งโอนสิทธิ์งานไปยัง AI ตัวถัดไปที่มีคุณสมบัติรองรับตามคิวลำดับความสามารถใน `personas.json` ทันที:
     ```bash
     node scripts/war-room.js takeover TASK_ID --from [ชื่อตัวเอง] --agent [ชื่อ AI ที่รับงานต่อ] --reason "Token limit warning"
     ```
   * การส่งมอบงานต้องแนบสรุปสถานะงานล่าลุดไว้ใน `handoff.md` เสมอ เพื่อให้อีกตัวรับช่วงต่อได้ในคลิกเดียว

## 🛠️ 4. คู่มือการเปิดใช้งานและแก้ปัญหา OpenClaw Trigger (OpenClaw Troubleshooting)

เมื่อพบปัญหา OpenClaw ไม่สามารถปลุกหรือส่งสัญญาณทริกเกอร์เรียก AI ตัวอื่น ๆ ได้หลังจากส่งต่องาน ให้ตรวจสอบสาเหตุดังนี้:

1. **ตรวจสอบสถานะ Watcher:**
   * หากพบว่าไม่มีการตอบรับ ให้รันคำสั่งเช็คสถานะ:
     ```bash
     npm run openclaw:status
     ```
   * หากแจ้งสถานะ `🔴 OpenClaw Watcher: NOT RUNNING` ให้ปลุกระบบขึ้นมาด้วยคำสั่ง:
     ```bash
     npm run openclaw:start
     ```
     *(หรือใช้ `npm run openclaw:watchdog` เพื่อให้ระบบคอยรีสตาร์ทตัวเองหากโปรเซสหลุด)*
2. **การอัปเดต Dependency หลังลง Windows ใหม่:**
   * หากลงวินโดว์ใหม่หรือสลับเครื่อง ตัวโปรแกรมเรียกประมวลผล AI ของเครื่องอาจสูญหาย (ไม่พบโฟลเดอร์ NPM Global)
   * แก้ไขได้โดยการรันติดตั้งคำสั่งสิทธิ์ Global ใหม่:
     ```bash
     npm install -g @google/gemini-cli @openai/codex @anthropic-ai/claude-code
     ```
     *(ติดตั้งสำเร็จแล้ว ตัวโปรเซสของ OpenClaw Watcher จะกลับมารันคำสั่งและปลุก AI แต่ละตัวได้เป็นปกติครับ)*

## 📦 5. กฎการทำงานแบบ Local-First และการ Push ครั้งเดียว (Single-Push Rule)

เพื่อป้องกันการแสดงหน้าต่างขออนุมัติข้าม Sandbox (Bypass Sandbox Prompt) เด้งรบกวนคุณ B3 บ่อยครั้ง ให้ AI ทุกตัวปฏิบัติตามกฎนี้อย่างเคร่งครัด:

1. **ทำงานและทดสอบแบบ Local ให้จบกระบวนการ:**
   * การแก้ไขโค้ด, เขียนสคริปต์, ตรวจสอบประเภทข้อมูล (tsc Check) และรัน Unit Test ทั้งหมด **ต้องทำภายใน Sandbox แบบ Local ให้เสร็จสิ้น 100% ใน session ก่อน**
   * ห้ามสั่ง `git push` หรือทำการเข้าถึงอินเทอร์เน็ตระหว่างทำงานในแต่ละไฟล์ย่อยโดยไม่จำเป็น
2. **รวบรวม Push ครั้งเดียวตอนจบงาน:**
   * เมื่อตรวจสอบความถูกต้องของชิ้นงานทั้งหมดจนแน่ใจว่าไม่มีข้อผิดพลาดแล้วเท่านั้น จึงจะรันคำสั่ง `git push` เพื่ออัปเดตโค้ดขึ้น GitHub ทีเดียวพร้อมกันตอนจบงาน
   * การทำแบบนี้จะทำให้หน้าต่างขออนุมัติข้าม Sandbox เด้งรบกวนคุณ B3 เพียงแค่ **ครั้งเดียวต่อหนึ่งชิ้นงาน** เท่านั้น
