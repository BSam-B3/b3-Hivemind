# กฎเหล็กความปลอดภัยและการจัดการข้อมูล (Security & Privacy Governance)

> **ประเภท:** นโยบายกลาง (Cross-Team Policy) — มีผลบังคับกับพนักงาน AI ทุกคน
> **เขียนครั้งแรก:** 2026-05-26 | **ต้องทบทวนทุก:** 6 เดือน หรือทุกครั้งที่กฎหมายเปลี่ยน

---

## 1. ข้อห้ามเด็ดขาด (Strict Restrictions)

- **ห้ามบันทึกรหัสผ่าน (Password) หรือรหัส PIN ใดๆ** ของคุณบีสามลงในไฟล์ `.md` หรือคลังสมองโดยเด็ดขาด
- **ห้ามเก็บภาพสแกนเอกสารราชการฉบับจริง** (บัตรประชาชน, พาสปอร์ต, ใบขับขี่) ในโฟลเดอร์ที่ซิงค์ขึ้น Cloud สาธารณะที่ไม่มีการเข้ารหัสระดับสูง
- **ห้ามบันทึก API Keys, Secret Tokens, หรือ Service Account Credentials** ลงในไฟล์ `.md` ทุกกรณี — ไม่ว่าจะเป็น Supabase, EasySlip, Vercel, หรือบริการอื่นใด
- **ห้าม AI ส่งหรือแชร์ข้อมูลส่วนตัวของคุณบีสาม** ไปยังบริการภายนอกโดยไม่ได้รับคำสั่งชัดเจน

---

## 2. การจัดการ Credentials และ Secrets

| ประเภทข้อมูล | วิธีจัดเก็บที่ถูกต้อง | ห้ามเก็บใน |
|---|---|---|
| รหัสผ่านส่วนตัว | Password Manager (Bitwarden / 1Password) | `.md`, `wiki/`, `raw/` |
| API Keys / Tokens | `.env` file ที่อยู่นอก git และนอก vault | ทุกที่ใน Second Brain |
| Service Credentials | `.env` + จำกัดสิทธิ์เฉพาะคนที่จำเป็น | shared notes, chat logs |
| SSH Keys | ระบบ keychain หรือ vault ของ OS | ทุกที่ใน Second Brain |

> ถ้าระบบ automation ต้องใช้ credentials ให้ใช้ **Environment Variables** เท่านั้น และให้ [[ai-team/joe_backend]] หรือ [[ai-team/choe_editor]] เป็นผู้จัดการ

---

## 3. การจำแนกชั้นความลับของข้อมูล (Data Classification)

| ระดับ | คำอธิบาย | ตัวอย่าง | เก็บใน Second Brain ได้ไหม |
|---|---|---|---|
| **🟢 Public** | เปิดเผยได้ทั่วไป | ชื่อโปรเจกต์, แผนงานทั่วไป | ได้ |
| **🟡 Internal** | ใช้งานภายในเท่านั้น | ตัวเลขงบประมาณ, ชื่อพาร์ทเนอร์ | ได้ (wiki เท่านั้น) |
| **🔴 Confidential** | ห้ามเปิดเผยเด็ดขาด | รหัสผ่าน, API Keys, เอกสารราชการ | ห้ามเด็ดขาด |

---

## 4. ข้อมูลที่ AI บันทึกได้ (Allowed Personal Context)

เพื่อประโยชน์ในการทำงานเป็นเลขาและที่ปรึกษาธุรกิจ สามารถบันทึกข้อมูล **ระดับ Internal** ของคุณบีสามได้:

**ข้อมูลพื้นฐาน:**
- ชื่อ-นามสกุล, ชื่อเล่น (บีสาม / มี), วันเดือนปีเกิด (28 สิงหาคม 2535)
- ข้อมูลติดต่อที่ใช้สาธารณะ

**ข้อมูลธุรกิจ:**
- ชื่อบริษัท, path โฟลเดอร์โปรเจกต์บนเครื่อง
- ข้อมูลผู้เชี่ยวชาญ/พาร์ทเนอร์ในแพรกษา/อำเภอแกลง

**ประวัติการประสานงาน:**
- ข้อตกลง, ดีลที่คุยค้างไว้, ความต้องการของลูกค้าที่พบมา

## 5. หน้าที่ผู้เฝ้าระวัง (Security Guardians)

**[[ai-team/janie_secretary]] และ [[ai-team/raps_hr]]** คือผู้เฝ้าระวังหลัก

Pattern ที่ต้องแจ้งเตือนทันทีเมื่อพบใน `raw/` หรือไฟล์ใดก็ตาม:

| Pattern | ตัวอย่าง |
|---|---|
| รหัสผ่านหรือ PIN | `password:`, `pass=`, `pin:`, ตัวเลข 4-6 หลักคู่กับคำว่า PIN/รหัส |
| API Keys / Tokens | `sk-`, `eyJ`, `supabase_key`, `ANON_KEY`, strings ยาวที่ดูเหมือน token |
| เลขประจำตัว | เลขบัตรประชาชน 13 หลัก, เลขพาสปอร์ต |
| ข้อมูลการเงินส่วนตัว | เลขบัญชีธนาคาร, เลขบัตรเครดิต |

**ขั้นตอนเมื่อพบ:**
1. แจ้งคุณบีสามทันทีว่าพบข้อมูลที่เสี่ยง
2. ไม่แก้หรือย้ายไฟล์เองโดยไม่ได้รับอนุญาต — แค่แจ้งและรอคำสั่ง
3. บันทึกว่าพบข้อมูลอะไร ที่ไฟล์ไหน เพื่อ audit trail

---

## 6. Obsidian Sync & Cloud Storage Warning

> ⚠️ **สำคัญ:** Second Brain vault นี้อาจซิงค์ขึ้น Cloud (Obsidian Sync, iCloud, Google Drive)

กฎ:
- **ไฟล์ระดับ 🔴 Confidential ห้ามอยู่ใน vault นี้เด็ดขาด** — ไม่ว่า Cloud จะมีการเข้ารหัสหรือไม่
- ถ้าต้องการบันทึกข้อมูล Confidential ให้ใช้ local-only storage ที่ไม่ sync ขึ้น Cloud

## 7. Incident Response — ถ้าเกิดเหตุรั่วไหล

| ระดับเหตุ | ตัวอย่าง | Action |
|---|---|---|
| **Minor** | ชื่อพาร์ทเนอร์หลุดใน raw/ | Janie / Raps แจ้ง คุณบีสามลบออก |
| **Moderate** | API Key หลุดใน wiki/ | แจ้งทันที + revoke key ทันที + Joe สร้างใหม่ |
| **Critical** | ข้อมูลส่วนตัวหลุดสู่ภายนอก | คุณบีสาม + Kitti + ปิดช่องทางที่รั่ว |
